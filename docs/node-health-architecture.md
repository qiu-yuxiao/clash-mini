# 节点健康与故障转移子系统 —— 从零开始的完整正确设计

> 设计原则：本子系统从地基就按"测量可靠、子集结构性、切换零断流、手动优先、自愈仅兜底"设计。
> 不基于任何现存实现做修补；现存 `monitor.rs` 守护线程属于被替换对象，不是被修改对象。

---

## 0. 不可妥协的硬约束

1. **测量可靠**：节点延迟的唯一权威来源，在 TUN 模式下绝不可出现"测活跃节点自身返回 timeout"这类自指回环。
2. **子集结构性**：地域框死的节点池是配置层事实，只能在池内选/保活，越界在结构上不可能发生。
3. **切换零断流**：故障转移一律干净热切换（`PUT /proxies/{group}`），禁止整份配置重载，绝不触发 `auto_close_connection` 断连风暴。
4. **手动优先**：用户选点（profile 切换时一次性触发 / 子集按钮）优先级最高且持久，除非该节点真实不可用。
5. **自愈仅兜底**：仅在"真实断网"或"子集内全部节点不可用"时介入，不靠不可靠的延迟自测驱动。

---

## 1. 分层架构（5 层，职责单一、互不越界）

### 第 1 层 · 测量（归 Mihomo 内核，app 完全不插手）
- `PROXY` 组 = `select` 策略（用户/app 控制，选择稳定、手动覆盖持久）。
- 新增**测量专用组** `PROXY__METRICS` = `url-test` 策略，`url`=测速地址，`interval`≈300s，`tolerance` 适当。
  其成员列表 = `PROXY` 组完全相同成员。
- Mihomo 按 `interval` 周期性**直接拨测**每个成员的真实延迟，维护 `now`/`history`。这是延迟的唯一真相源。
- **为什么正确**：测量交给 Mihomo 内核的 url-test——这是上游 Clash Verge Rev 经大规模验证的可靠机制，在 TUN 下无回环问题。app 层不再通过 `/delay` API 自测任何节点健康，旧设计在 TUN 下失效的根被从测量源消除。

### 第 2 层 · 子集语义（结构性，非 app 逻辑补丁）
- 地域过滤（`filterText`）决定两个组的**成员列表**。改过滤 = 用同一份节点名列表同时重配 `PROXY` 与 `PROXY__METRICS` 的 membership。
- 池外节点在两个组里根本不存在 → 越界在配置层即不可能。

### 第 3 层 · 故障转移 / 自愈（app 侧，仅可靠信号）
- app **不再轮询"活跃节点自身延迟"**。改为订阅两类可靠信号：
  - (a) **测量组状态**：`PROXY` 当前选中节点在 `PROXY__METRICS` 中 `now==0/不可用`，且测量组存在健康成员 → 发 `select` 切到最佳健康成员。
  - (b) **真实网络连通性**（`is_online` 端到端探测，守护线程已有）→ 真断网时安静等待，不抖动切节点。
  - (c) **全死检测**：测量组所有成员均不可用 → 告警 / 触发恢复流程。
- 切换一律 `select`（干净热切换），**永不整份 reload**，绝不触发断连风暴。

### 第 4 层 · 手动覆盖（保留，原 F1/F2/F4 入口）
- profile 切换/导入时的一次性选点、子集按钮的选点 = 显式用户指令，优先级最高。
- app 把用户选定节点 `select` 到 `PROXY`；故障转移层尊重此选择，直到该节点在测量组变为不可用。

### 第 5 层 · 展示
- UI 延迟直接读 `PROXY__METRICS` 的 `now`/`history`（权威值），不再由 app 写入独立缓存再回写。
- `DelayManager` 退化为测量组状态的只读透传，或移除其自测回写路径。

## 2. 关键设计决策与理由（替你拍板的部分）

**决策 1：用独立测量组 `PROXY__METRICS`，而非把 `PROXY` 直接改成 `url-test`。**
- 若 `PROXY` 是 `url-test`，Mihomo 每个 `interval` 会自动翻选，与"手动选点持久"冲突（手动选点会被内核翻回）。
- `select` 组（控制）+ 独立 `url-test` 组（测量）把"测量"与"控制"彻底解耦：手动选点持久，测量又可靠。两者兼得，无冲突。

**决策 2：旧 `monitor.rs` 守护线程整体替换，不是删某一行。**
- 它的设计前提是"后端能可靠测活跃节点自身延迟"——该前提在 TUN 下不成立，整条链路从测量源就错。任何在其内部的加减法都是贴膏药。新设计里它由"订阅测量组 + 可靠信号 failover"的薄逻辑取代。

**决策 3：禁 reload，只热切换。**
- 旧设计 `refresh_clash()` 整份重载 + `auto_close_connection` 是真实断流推手；`select_node_for_group` 干净热切换不断连。

## 4. 验证标准（设计正确的判定依据）

1. TUN 模式下连续运行 30+ 分钟：健康节点数不递减、不全 timeout、无断流。
2. 子集外节点永不出现在选择 / 故障转移候选中（配置层保证）。
3. 手动选点后，在"该节点真实不可用"之前保持选中，不被内核翻回。
4. 真实断网时程序安静等待，不抖动切节点、不触发断连风暴。
5. `PROXY__METRICS` 的 `now` 值在全量节点上均为真实延迟（无系统性 0）。
