# Analysis: tauri-plugin-mihomo Upgrade and Audit

This report investigates the upgrade of `tauri-plugin-mihomo` from version `0.5.2` to `0.5.4` and checks its connection to layout/rendering issues. It also audits patches, build scripts, batch files, and bindings.

## 1. Summary of Version Upgrade

The upgrade history of `tauri-plugin-mihomo` reveals the following timeline:
- **Upgrade from 0.3.0 to 0.5.2** (Commit `3b693842` on 2026-06-14): This upgrade WAS performed to resolve a critical rendering issue ("white screen") when the application started.
- **Path Dependency and Local Patching** (Commit `df8ab1ef` on 2026-06-14): The plugin was converted from a Git dependency to a local path dependency under `crates/tauri-plugin-mihomo` to apply the lowercase deserialization patch for `FindProcessMode` and `LogLevel` enums.
- **Upgrade from 0.5.2 to 0.5.4** (Commit `579532ad` on 2026-06-22): This upgrade was a version-only bump in `crates/tauri-plugin-mihomo/Cargo.toml` and `Cargo.lock`. It was done to satisfy the upstream version verification in `verify.py`, which checks the latest upstream version from GitHub.

## 2. Relation to Layout / Rendering Issues

- The upgrade to **0.5.4** is **not** related to any layout or rendering issues. It was purely a metadata version bump to pass `verify.py` validation.
- The layout and rendering issues (such as `BUG-215` and `BUG-203` in `bug_list.md`) are caused by strict Content Security Policy (CSP) blocking Emotion's dynamically injected styles and external Google Fonts, causing the UI to fallback or collapse. These are solved via CSP adjustments and locally bundling fonts/using inline MUI style workarounds, independent of the `tauri-plugin-mihomo` version.

## 3. Audit of Patches, Scripts, and Bindings

### A. Patches (LogLevel & FindProcessMode)
- The local patch is located in `crates/tauri-plugin-mihomo/src/models.rs`.
- The attributes `#[ts(export, rename_all = "lowercase")]` and `#[serde(rename_all = "lowercase")]` are applied to both the `LogLevel` and `FindProcessMode` enums.
- These patches remain intact in the local version 0.5.4 and have not been deleted. They prevent setting state bounce issues (specifically BUG-072).

### B. Build Scripts & Batch Files
- There are no deleted or missing batch files (`.bat`/`.cmd`) or shell scripts (`.sh`) for building JS assets or bindings.
- `crates/tauri-plugin-mihomo/build.rs` compiles the plugin commands to Tauri but does not compile TS/JS assets.
- `scripts/prebuild.mjs` handles downloading the mihomo core sidecar files but is not involved in compiling the plugin's frontend.

### C. Bindings and JS Assets Rebuilding
- **TypeScript Bindings**: Generated by the `ts-rs` crate via `#[ts(export)]` macro attributes in Rust models when running `cargo test`.
- **Javascript Assets**: Compiled using Rollup from `guest-js/index.ts` to `dist-js/` via the script `pnpm build` defined in `crates/tauri-plugin-mihomo/package.json`.
- **Workflow / Execution Requirement**: Because the root project links to the local package (`"tauri-plugin-mihomo-api": "link:./crates/tauri-plugin-mihomo"`), any future updates to the plugin's models/functions must be manually compiled by running:
  1. `cargo test --package tauri-plugin-mihomo` (to regenerate TS bindings in `guest-js/bindings`)
  2. `cd crates/tauri-plugin-mihomo`
  3. `pnpm install`
  4. `pnpm build` (to compile rollup bundle in `dist-js`)
  
  These steps are not automated by root scripts or hooks.
